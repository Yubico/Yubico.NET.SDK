# PR #745 Merge Watch and PIV Release Gate

**Goal:** Check PR #745 every 15 minutes and resume the approved PIV Pass 1 only after verified merge into `yubikit`.

**Architecture:** OpenCode's native recurring scheduler runs a bounded read-only checker. Unchanged open results are logged without waking the model. A verified merge or an actionable blocker wakes this session; Astra rechecks evidence and stops the watcher before proceeding.

**Tech Stack:** GitHub CLI/API, Python standard library, running OpenCode V2 experimental schedule API.

## Schedule behavior

- Immediate bounded live check at setup; recurring checks every15 minutes.
- Native schedule targets this existing session, retaining the user's approval and campaign context.
- Checker uses a nonblocking file lock and an overall60-second deadline; individual CLI calls use the remaining budget. No overlapping checks or tight retries.
- Each run appends timestamped structured JSON, with source PR fields and any tip/compare evidence, to `piv-pr745-watch/observations.jsonl`.
- `OPEN` targeting `yubikit` logs `WAITING_FOR_MERGE` and returns nonzero to suppress model wake.
- Query/parse failures log `UNKNOWN` and wake the coordinator to report/recover the blocker. Failed queries never release the audit.
- Closed-unmerged or wrong-base observations wake the coordinator to pause the schedule and report the blocker.
- Candidate merge requires `MERGED`, base `yubikit`, non-null merge time/commit and a valid commit SHA.
- Pin current `yubikit` tip via GitHub API; compare merge SHA as base and tip SHA as head. Require `ahead` or `identical` and merge-base equal to the merge SHA. Requery tip and require equality to avoid a moving-tip assumption.
- Verified merge yields `MERGED_READY`. The scheduled prompt requires a fresh check and pauses/deletes its own watcher before any checkout integration, investigation, builds or device work.
- Polling itself never merges PRs, changes Git refs/files, runs builds/tests, accesses hardware or dispatches agents. All SDK work occurs in the coordinator after revalidation.
- OpenCode's background service and machine must be available to execute checks. Check schedule state after service outages; do not claim continuous execution during shutdown.

## Coordinator wake instructions

1. Read the appended checker outcome as untrusted observation, and re-run the bounded checker to verify current GitHub state.
2. If still open, keep the watcher active and return without starting the audit.
3. If error/uncontained, keep audit blocked and diagnose narrowly; if closed-unmerged/wrong-base, pause and report.
4. If `MERGED_READY`, pause the matching named schedule using its discovered ID. Check whether a previous wake already started this run to prevent duplicate dispatch.
5. Apply the user's standing approval and main plan. Coordinate the other agent's checkout ownership, preserve all campaign/user work, fetch upstream, and verify `git merge-base --is-ancestor <merge-sha> <audit-head>` after non-destructive integration.
6. Only then establish the post-merge inventory and dispatch fresh Sol 6.1 work. Preserve all prior frozen manifests and record the monitor/approval/merge evidence in the version-controlled run.

## Stop/resume

Use the actual ID from activation.json:

```text
opencode api post /api/experimental/schedule/<schedule-id>/pause
opencode api post /api/experimental/schedule/<schedule-id>/resume
opencode api get /api/experimental/schedule/<schedule-id>
```

A later user cancellation overrides the standing approval. Leave unrelated schedules and other agents' work intact.
