## Independent oracle and original sources

[`sources/provenance.json`](../validation/hardware-probe/sources/provenance.json) records original
URLs, retrieval timestamps, complete response sizes/SHA-256 identities, focused excerpt ranges
and excerpt hashes. The vendor source is `Yubico/python-yubihsm`, commit
`44a5ab52e0697c67b36c6dec953db08a6b7b183a`, `yubihsm/core.py`, response SHA-256
`00257ee2e85f1dafde5d5978aecdac6ec23e42aa7d2ef464bdc54f90e6fbbb7f`.
Its `_derive`, constants and `SymmetricAuth.create_session`/`authenticate` establish this mapping:

- Input: `00[11] || type || 00 || L[2, big endian] || 01 || context[16]`.
- S-ENC: CMAC(K-ENC, type `04`, L=128); S-MAC/S-RMAC: CMAC(K-MAC, types `06`/`07`, L=128).
- Synthetic valid card cryptogram: first eight bytes of CMAC(S-MAC, type `00`, L=64).

The independent local CMAC uses only .NET AES block encryption. RFC 4493 (June 2006,
**Informational**), sections 2.3–2.4 and all four section-4 vectors, supplies the subkey/padding
algorithm and primitive known answers. Every lane runs those four vectors before hardware binding.
The implementation uses `Aes.SetKey(ReadOnlySpan<byte>)` and span-destination `EncryptEcb` with
`PaddingMode.None`; their .NET 10 API documentation was checked through Context7. ECB here supplies
the single-block AES primitive inside CMAC. Each successful device calculation compares all three
16-byte outputs with `CryptographicOperations.FixedTimeEquals`.

The fixed context and card cryptogram are laboratory inputs generated by the host. This establishes
whether the YubiKey's calculation matches that host calculation for the recorded inputs. Live
connector/HSM authentication, HSM session establishment and HSM conformance remain separate work.

## Four lanes and acceptance

| Lane / method prefix | Required evidence |
| --- | --- |
| `KnownAnswer_OneWrongPassword` | Fresh non-touch credential starts at 8. Calculation without optional cryptogram matches all three keys. Exactly one wrong credential-password CALCULATE produces `HsmAuthRetryException`, SW `63C7`, INS `03`, typed retries 7 and LIST retries 7. A correct calculation with the independently generated valid card cryptogram matches all keys and LIST returns 8. Management retries remain 8; the prompt stays silent. |
| `PasswordTransitions_UserAndAdmin` | Each actor receives a fresh non-touch credential. User P1=0 and admin P1=1 password-change calls are measured separately. A successful transition requires new-password calculation with all three host-matched keys and retries 8. Exact CALCULATE-independent change-command SW `6D00`, INS `0B`, matching P1 is recorded as **capability-blocked**; the old password must still produce the known answer. Both actors are attempted, then final cleanup runs. Any blocked actor makes the test skipped with an explicit reason, rather than a successful transition. Other exceptions fail the lane. |
| `HumanTouch_Calculate` | Human-ready invocation only, tagged `RequiresUserPresence`. Fresh touch-required credential, real CALCULATE and valid synthetic card cryptogram. Require exactly one `PolicyRequires` request and one same-context `Completed` resolution using `CancellationToken.None`, all three host-matched keys, and retries 8. Coordinator records physical touch timing; a policy notification alone establishes the SDK's pre-command policy signal. |
| `NoTouch_CancelAfterPolicyOpportunity` | Keep hands off the key. Run touch-required CALCULATE on a separately scheduled task. Observe its pre-APDU `PolicyRequires` notification, allow at least one second for command admission, confirm the operation remains incomplete, then cancel. Drain that same task before disposing. Accept only a caller `OperationCanceledException` with one `Cancelled` resolution, or measured CALCULATE SW `6985` with one `Failed` resolution. Log elapsed/drain time and exact exception/status. The latter is a device-status observation after cancellation; cancellation effectiveness and touch timeout remain unproven. After disposal, a fresh SmartCard session must LIST, delete/recreate a non-touch credential and produce the independent three-key answer, without an intervening reset. |

The cancellation lane gives the command an admission opportunity; public policy callbacks supply
no native-admission acknowledgement or `DeviceWaiting` status. Its logs retain that limitation.
The two accepted observable outcomes have separate classifications. Any early completion,
controller failure, unexpected exception/status, body watchdog expiry or lifecycle mismatch fails.
The four lanes cover the useful questions proportionately; a separate natural no-touch wait would
add device-timeout policy questions and remains outside this preparation.

Each lane resets through an owned session, disposes it and reopens a fresh session to require an
empty LIST and management retries 8 before its body. A `finally` block attempts reset and fresh
readback again, using independent tokens and new owned connections; it gets two bounded attempts.
Cleanup proceeds even when the body or a previous LIST failed. Body and cleanup failures are
retained together. Fresh cleanup verifies **YubiHSM Auth only**; other applets keep their state.
Caller-owned management/password/static-key/context/oracle/cryptogram buffers are cleared by
`SymmetricFixture.Dispose`; CMAC scratch spans are cleared in `finally`, AES objects are disposed,
and every returned `SessionKeys` container is disposed, including unexpected cancellation success.
Output records metadata, statuses, timing and comparison results; it carries no secret bytes.

## Bounds and coordinator commands

After harness binding, each case has an **80-second cooperative budget**: body at most 60 seconds,
touch/cancellation operation watchdog at most 35 seconds, and two cleanup attempts of at most
8 seconds each within the remaining case budget. Native I/O, session opening/disposal and harness
discovery can block beyond cooperative cancellation. VSTest's **120-second process limit** is the
last-resort bound, separate from a device timeout. The code always drains the actual operation;
its controller's `WaitAsync` deadline never substitutes for draining device I/O. A host kill can
prevent `finally`: stop, retain the failure, and have the coordinator perform independent fresh
reset/empty-LIST/retries-8 readback before another lane. Preserve that cleanup as separate evidence.
