# Core boundary inventory

This is a test-only, Core-only scanner of `src/Core/src/**/*.cs` (excluding `bin` and `obj`). It does not inspect applet projects, NativeShims, the generated native implementation, runtime behavior, or platform-specific binaries. The checked-in `core-boundaries.v1.json` is a reviewed **source-site classification**, not an async-safety attestation.

The current baseline classifies 219 sites: 132 native imports, 3 native exports, 37 blocking waits (including native-worker parking, bounded joins, nonwaiting admission, console polling and synchronous compatibility/disposal drains), 18 scheduling sites, 21 pre-task-return dispatch gaps, 6 callback registrations, 0 delegate-to-function-pointer conversions and 2 unmanaged callback addresses. L3 replaces the Linux direct IO facade's Task.Run disposal site with one native owner worker (two mutually exclusive context-start sites), four owner waits and three synchronous facade waits. L4 independently removes feature-facade Task.Run disposal, adds the OTP owner's two waits and two mutually exclusive native-worker start sites, and three synchronous feature-facade waits. L2's private eventfd retirement stays on the poller; device-reference release is an explicit synchronous action on the original FIDO native owner worker after actual quiescence. OTP feature ioctls never use the reactor. Each entry has an exact-site identity and every family is `documented` and `outstanding`: no entry is marked implemented or verified by this scanner. Native declarations remain synchronous; the inventory does not establish their callers' platform behavior.

The scanner compiles Core sources with the runtime's trusted assemblies, the test output's dependency assemblies, implicit .NET usings and the installed .NET 10 LibraryImport generator. It fails on semantic compile errors rather than falling back to text matching. Its site key is `relative-path|fully-qualified-containing-symbol|kind|fully-qualified-target|ordinal-within-that-group`; a method rename or changed target makes an entry stale. Ordinals identify repeated operations of the same kind within one method. Manifest entries carry an explicitly recorded method name plus the first 12 hex characters of the SHA-256 digest of the full key; the complete key is recomputed from source during the test. No digest or classification is generated in the passing test.

`adapter-contracts.v1.json` is a separate, bounded **test-only link registry**. Its original 27 rows / 49 profile links (not executed-case counts) remain required: typed macOS FIDO (4), typed macOS OTP (4), portable PCSC open/transmit/transaction begin/end/dispose (5), synchronous macOS direct input (4), direct feature (4), listener start/stop (2), and synchronous portable PCSC begin/end/dispose plus external default async begin (4). L6a extends this scope below without shrinking those requirements. The gate rejects missing, extra, duplicate, empty and stale rows, wrong owner/method mappings, and missing/repeated behavioral roles. It resolves production owner types/methods and runnable declared Fact/Theory methods. Roles identify managed evidence, not exhaustive branch coverage. Registry validation **links tests but does not run them recursively** or attest native behavior. Run normal tests separately; portable PCSC fake-managed evidence is not platform-driver execution.

L6a adds 16 independently required Linux rows / 27 runnable profile links: typed FIDO and OTP open/send/receive/dispose (8), and direct synchronous IO/feature open/get/set/dispose (8). Totals are **43 rows / 76 links**; the original 27 rows / 49 links are preserved. Deleting any Linux row or role fails closed. Profiles cover pending calls, cancellation, owned buffers, terminal reads, true-quiescence/checked-close drain and release failure under native fakes below production owners. `LinuxDirectFacadeAcceptanceTests` adds retained synchronous facade evidence. Windows HID remains explicitly deferred and rejected; Linux links do not certify kernel/hidraw behavior. Direct macOS/Linux rows classify retained caller waits, not nonblocking entry points.

`PublicSyncBoundaryRegistry` independently pins **24** public synchronous or synchronous-dispatch reachability entries: direct macOS input/feature (8), direct Linux input/feature (8), built-in SmartCard begin/scope end/dispose plus custom async fallback (4), macOS listener start/stop (2), manager shutdown (1), HID scan dispatch (1). It resolves both public and owner symbols and runnable evidence separately from adapter profiles. Removing any Linux public entry fails closed. The registry links reachability, not native drain; it does not cover Windows reports, arbitrary custom implementations, or every SDK public boundary. The new PC/SC held disconnect/context-release and live registered failure/rooting tests are portable managed evidence, not Linux-driver acceptance. See [L6a evidence](../../../../../docs/research/linux-managed-acceptance.md).

Version 1 families require an exact `path`, assigned `reviewOwner` (Core maintainer role), family `rationale`, source `evidence`, `status` (array of `outstanding`, `documented`, `implemented`, `verified`) and explicit per-site `entries`. Every native import is listed by `method#digest` and receives a family rationale plus its resolved target. Every other entry must be `method#digest#execution#justification` with execution `sync-boundary`, `async-blocked`, `worker`, or `callback`. No wildcard, directory or runtime-category waiver exists: a passing gate requires every detected site classified, no stale or duplicate sites, and valid evidence. `outstanding` is never `verified`.

Coverage is deliberately narrower than a whole-program proof. The scanner uses the .NET 10 target's preprocessor symbols, not a multi-target build evaluation; any unrecognized conditional symbol fails the scan. Native imports, selected dynamic exports, task waits/results/awaiter `GetResult` including configured awaiters, `WaitHandle.WaitOne/WaitAll/WaitAny`, `ManualResetEventSlim.Wait`, `SemaphoreSlim.Wait`, `Thread.Join`, `Thread.Sleep`, `Monitor.Wait`, scheduling, `LongRunning`, native delegate registrations, Marshal delegate conversion and address-taken `UnmanagedCallersOnly` methods are recognized by resolved symbols. Direct known blocking leaves and interface calls in task-returning methods (including generic task and value-task methods) before returning their task are reported as `dispatch-gap`; scheduled worker delegates are **not** falsely classified as caller-thread blocking. Interface dispatch alone is an unresolved gap, not proof that every implementation blocks. Other indirect dispatch, reflection, `dynamic`, indirect function-pointer calls, nested callees, conditional compilation for other targets and platform behavior need separate review. In particular the scanner cannot verify that an `async` signature does not conceal a blocking operation reached through arbitrary calls. It does not prove exception reviews are current or native cross-platform behavior.

### Scoped public wait and diagnostic disposition

The [raw-access tiers map](../../../../../docs/architecture/raw-access-tiers.md#retained-synchronous-compatibility-paths) identifies public reachability independently of syntactic waits: macOS/Linux report constructors/Get/Set/Dispose, smart-card transaction begin/end, `IConnection.Dispose`, manager/listener shutdown, internal OTP Configure, HID scan dispatch, Windows/custom slot fallback, and interface forwarding. Worker parking and nonwaiting admission are not public waits. L6a changes no shipping source sites: **219 sites / 132 imports / 37 waits / 18 scheduling sites** remain classified, documented/outstanding, not globally verified. Public YubiOTP awaits status before Configure; its latent internal wait is retained. Neither these links nor the manifest proves whole-program coverage, after-dispatch enumeration drain, or Linux hardware acceptance.

For diagnostics, `MigrationDiagnosticsTests` parses logger calls in `UsbSmartCardConnection`, `MacOSFidoHidConnection`, `MacOSOtpHidConnection`, `PcscProtocol`, `FindHidInterfaces` and `PcscConnectionSlot`; it also uses the real logger provider for PC/SC connection, OTP recovery and APDU protocol command/response sentinel checks, including structured state and exception text. A negative result for those secrets does not make a SELECT application identifier or caller-provided exception message safe to log in every context: both have unresolved provenance. Logging in `FidoHidProtocol`, `OtpHidProtocol`, `ProtocolDeviceInfo`, `DiscoveryIdentityReader`, `FindYubiKeys`, `YubiKeyDeviceMonitorService` and platform listeners still requires review of templates and externally supplied values. SDK-generated payload serialization is distinct from what an arbitrary caller logger does with supplied arguments or an external exception's own message. These tests do not establish a whole-SDK no-leak guarantee.
