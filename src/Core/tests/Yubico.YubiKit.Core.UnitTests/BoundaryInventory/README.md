# Core boundary inventory

This is a test-only, Core-only scanner of `src/Core/src/**/*.cs` (excluding `bin` and `obj`). It does not inspect applet projects, NativeShims, the generated native implementation, runtime behavior, or platform-specific binaries. The checked-in `core-boundaries.v1.json` is a reviewed **source-site classification**, not an async-safety attestation.

The current baseline classifies 198 sites: 130 native imports, 18 blocking waits (including native-worker parking, bounded joins, nonwaiting admission and console polling), 17 scheduling sites, 21 pre-task-return dispatch gaps, 6 callback registrations, 4 delegate-to-function-pointer conversions and 2 unmanaged callback addresses. Each entry has an exact-site identity and every family is `documented` and `outstanding`: no entry is marked implemented or verified by this scanner. Some native declarations (for example, Windows and Linux HID/PCSC) remain synchronous at their call sites.

The scanner compiles Core sources with the runtime's trusted assemblies, the test output's dependency assemblies, implicit .NET usings and the installed .NET 10 LibraryImport generator. It fails on semantic compile errors rather than falling back to text matching. Its site key is `relative-path|fully-qualified-containing-symbol|kind|fully-qualified-target|ordinal-within-that-group`; a method rename or changed target makes an entry stale. Ordinals identify repeated operations of the same kind within one method. Manifest entries carry an explicitly recorded method name plus the first 12 hex characters of the SHA-256 digest of the full key; the complete key is recomputed from source during the test. No digest or classification is generated in the passing test.

`adapter-contracts.v1.json` is a separate, bounded **test-only link registry**. Its independent required-operation list covers 13 rows: macOS FIDO (open, send, receive, dispose: 4), macOS OTP (open, send, receive, dispose: 4), and portable PCSC (open, transmit, transaction begin, transaction end, dispose: 5). The gate rejects missing, extra, duplicate, empty and stale rows, wrong owner/method mappings, and missing or repeated behavioral roles per operation. It resolves Core owner types (including the private nested PCSC transaction scope) and declared methods, and resolves named Core unit-test Fact/Theory methods through the test assembly. Roles identify managed evidence such as pending dispatch, cancellation before/during native work, overlap, drain and failure; they do not prove that every branch is covered. Registry validation does **not** run tests recursively or attest native behavior on another operating system. Run the normal Core unit suite separately for behavioral evidence. Portable PCSC managed tests executed on macOS are not Windows/Linux native execution.

Deferred, without passing coverage rows: Windows HID FIDO/OTP open/send/receive/dispose; Linux HID FIDO/OTP open/send/receive/dispose. These are outside the required registry; adding them as verified rows fails validation rather than claiming migrated operation profiles. This registry supplies only partial evidence for registry criterion 4, not completion of the async-boundaries epic.

Version 1 families require an exact `path`, assigned `reviewOwner` (Core maintainer role), family `rationale`, source `evidence`, `status` (array of `outstanding`, `documented`, `implemented`, `verified`) and explicit per-site `entries`. Every native import is listed by `method#digest` and receives a family rationale plus its resolved target. Every other entry must be `method#digest#execution#justification` with execution `sync-boundary`, `async-blocked`, `worker`, or `callback`. No wildcard, directory or runtime-category waiver exists: a passing gate requires every detected site classified, no stale or duplicate sites, and valid evidence. `outstanding` is never `verified`.

Coverage is deliberately narrower than a whole-program proof. The scanner uses the .NET 10 target's preprocessor symbols, not a multi-target build evaluation; any unrecognized conditional symbol fails the scan. Native imports, selected dynamic exports, task waits/results/awaiter `GetResult` including configured awaiters, `WaitHandle.WaitOne/WaitAll/WaitAny`, `ManualResetEventSlim.Wait`, `SemaphoreSlim.Wait`, `Thread.Join`, `Thread.Sleep`, `Monitor.Wait`, scheduling, `LongRunning`, native delegate registrations, Marshal delegate conversion and address-taken `UnmanagedCallersOnly` methods are recognized by resolved symbols. Direct known blocking leaves and interface calls in task-returning methods (including generic task and value-task methods) before returning their task are reported as `dispatch-gap`; scheduled worker delegates are **not** falsely classified as caller-thread blocking. Interface dispatch alone is an unresolved gap, not proof that every implementation blocks. Other indirect dispatch, reflection, `dynamic`, indirect function-pointer calls, nested callees, conditional compilation for other targets and platform behavior need separate review. In particular the scanner cannot verify that an `async` signature does not conceal a blocking operation reached through arbitrary calls. It does not claim universal criterion 7 or native cross-platform behavior.
